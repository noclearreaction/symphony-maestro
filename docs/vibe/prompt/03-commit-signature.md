# Fragment 3 — Commit signature

| | |
| --- | --- |
| **Position** | After the headless fragment |
| **Gate** | `include_commit_signature` (default `true`) |
| **Source** | Compiled into the binary |
| **Measured** | 393 chars |

Instructs the model to attribute every commit to Mistral Vibe. It is appended
after the base prompt, so it overrides commit conventions stated in a custom
prompt — a project with its own trailer policy will see this fragment fight it.

## Disabling

```toml
# config.toml
include_commit_signature = false
```

```bash
VIBE_INCLUDE_COMMIT_SIGNATURE=false vibe ...
```

Disabling removes 394 chars.

## Content

Static text, no interpolation. Note the nested fenced block — the fragment itself
contains a ```` ```bash ```` example, which is why it is quoted here at four
backticks.

````markdown
When you want to commit changes, you will always use the 'git commit' bash command.
It will always be suffixed with a line telling it was generated by Mistral Vibe with the appropriate co-authoring information.
The format you will always uses is the following heredoc.

```bash
git commit -m <Commit message here>

Generated by Mistral Vibe.
Co-Authored-By: Mistral Vibe <vibe@mistral.ai>
```
````

## Example

The text above is the fragment exactly as it appears on the wire — including the
`you will always uses` grammatical error, and the fact that the illustrated
`git commit -m` form is described as a heredoc but is not one.

Resulting commit trailer:

```
Generated by Mistral Vibe.
Co-Authored-By: Mistral Vibe <vibe@mistral.ai>
```

This repository's own convention differs, so leave the flag enabled only if the
Mistral attribution is wanted on commits authored through Vibe.
